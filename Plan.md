# План тестирования мобильного приложения «Мобильный хоспис»

## 1. Объект тестирования

Мобильное приложение «Мобильный хоспис».

## 2. Цель тестирования

Проверить корректность работы основного функционала мобильного приложения «Мобильный хоспис» и подготовить тестовую документацию для дальнейшей автоматизации.

## 3. Границы тестирования

### В рамках тестирования проверяется:

- авторизация пользователя;
- главный экран приложения;
- навигация между разделами приложения;
- раздел новостей;
- просмотр новостей;
- создание новостей;
- редактирование новостей;
- удаление новостей;
- фильтрация новостей;
- сортировка новостей;
- раздел тематических цитат;
- раздел «О приложении»;
- выход из учётной записи.


## 4. Виды тестирования

В рамках проекта будут использоваться следующие виды тестирования:

- функциональное тестирование;
- UI-тестирование;
- позитивное тестирование;
- негативное тестирование;
- регрессионное тестирование.

## 5. Тестовая среда

- Устройство: Android-эмулятор или реальное Android-устройство.
- Версия Android: API 29.
- Среда разработки: Android Studio.
- Язык автотестов: Java / Kotlin.
- Фреймворк для UI-тестов: Espresso / UI Automator.
- Отчётность: Allure.

## 7. Документация по итогам первого этапа

В результате выполнения дипломного проекта будут подготовлены следующие артефакты:

- Plan.md — план тестирования и автоматизации приложения;
- Check.xlsx (или Check.csv) — чек-лист тестирования приложения с результатами выполнения проверок;
- Cases.xlsx (или Cases.csv) — набор тест-кейсов для проверки функциональности приложения;
- UI-автотесты для проверки основного функционала приложения;
- README.md с описанием процедуры запуска авто-тестов;
- allure-results.zip с отчётом о результатах прогона тестов (Allure);
- Result.md с результатом сравнения времени проверки приложения по чек-листу руками и UI-тестами.
